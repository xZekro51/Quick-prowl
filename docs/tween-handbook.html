Quick start

There is nothing to set up. The first tween you create spawns a hidden Tween Master object that ticks every tween from the engine loop and survives scene loads for the rest of the play session. Animate a transform in one line:

using Prowl.Runtime;
using Prowl.Tweening;
using Prowl.Vector;

public class Door : MonoBehaviour
{
    public override void Start()
    {
        Transform.Move(new Float3(0, 3, 0), 1.5f)
                 .SetEase(Ease.OutBack)
                 .SetLoops(-1, LoopType.Yoyo);
    }
}

Anything that isn't a transform goes through Tween.To. Describe the tween, then Bind it to the thing it writes to — passing that thing as state keeps the setter a static lambda, which is what makes the call allocation-free:

Tween.To(Shown, health, 0.4f)
     .Bind(this, static (v, self) => self.Shown = v)
     .SetEase(Ease.OutCubic);

Every call returns a Tween handle for chaining. A handle is a 12-byte struct, not an object: store it, copy it, ignore it. Operations on a tween that has already finished simply do nothing.

Creating tweens

There are four ways in. They differ in where the start value comes from and in what they cost; pick the first one that fits.

From explicit values, with Bind

Tween.To(from, to, duration) returns a builder. Nothing runs until you call Bind(state, setter), Bind(setter), or BindNothing() for a tween that only exists for its callbacks. Built-in overloads cover float, double, int, long and the System.Numerics vectors and quaternion; Tween.To<T, TAdapter> covers anything else.

From the current value

When the start is “wherever it is now”, pass a getter too. The state overload reads it once, when the tween starts — after any delay, or when a sequence reaches it — and still allocates nothing:

Tween.To<float, FloatAdapter, Material>(
    material,
    static m => m._properties.GetFloat("_Dissolve"),
    static (v, m) => m.SetFloat("_Dissolve", v),
    1f, 0.8f);

Engine math types

ProwlTween gives Float2, Float3, Float4, Quaternion and Color the same short spelling. It lives in Prowl.Runtime so the core library stays free of engine types.

// Builder form: you supply the start value.
ProwlTween.To(Tint, new Color(1f, 0.25f, 0.25f, 1f), 0.15f)
          .Bind(this, static (v, self) => self.Tint = v);

// State form: the start value is read from the object.
ProwlTween.To(this, static s => s.Tint, static (v, s) => s.Tint = v,
              new Color(1f, 1f, 1f, 1f), 0.3f);

The convenient form

Capturing lambdas read naturally and are fine in code that runs occasionally. On a hot path, use one of the forms above.

// Reads well, but allocates two delegates and a closure on every call.
Tween.To(() => Shown, v => Shown = v, health, 0.4f);

Transform shortcuts

Extension methods on Transform. Each reads its start value when it starts playing — after any delay, or when a sequence reaches it — tags the tween with the transform (so Tween.KillAll(transform) finds it), and links it to the transform's GameObject so it dies with the object instead of writing to a destroyed one.

MethodAnimates
Move(Float3 to, float duration)World position
MoveX / MoveY / MoveZ(float to, float d)One world axis, leaving the others alone
LocalMove(Float3 to, float d)Position relative to the parent
LocalMoveX / Y / Z(float to, float d)One local axis
RotateTo(Quaternion to, float d)World rotation, shortest arc
RotateTo(Float3 euler, float d)World euler angles in degrees, interpolated as raw numbers
LocalRotateTo(Quaternion | Float3, float d)Rotation relative to the parent
LookAt(Float3 target[, Float3 up], float d)Turn to face a point (target is read once)
Scale(Float3 | float to, float d)Local scale; a float scales uniformly
ScaleX / ScaleY / ScaleZ(float to, float d)One scale axis
KillTweens(bool complete = false)Kills every tween targeting this transform, returns the count

The rotation method is called RotateTo rather than Rotate on purpose: Transform already has an instance Rotate(Float3, float), and it would win over an extension method and snap instead of tweening.

Configuring a tween

Chain settings straight after creation. Order doesn't matter, and every call is a no-op on a dead handle.

Tween.To(0f, 1f, 0.6f)
     .Bind(this, static (v, self) => self.Shown = v)
     .SetEase(Ease.OutElastic, 1.2f, 0.4f)
     .SetDelay(0.25f)
     .SetLoops(3, LoopType.Yoyo)
     .SetAutoKill(false)
     .SetUpdate(UpdateType.Late, isIndependentUpdate: true)
     .SetTimeScale(1.5f)
     .SetId("hud")
     .SetTarget(this)
     .SetLink(GameObject, static go => go.IsValid());
SettingDefaultNotes
SetEase(Ease)OutQuadOr Tween.DefaultEase if you changed it. Ease.Unset means “the default”.
SetEase(Ease, overshoot[, period])1.70158, 0Overshoot for Back, amplitude and period for Elastic. Period 0 picks the standard 0.3.
SetEase(EaseFunction)—A custom curve; cache the delegate.
SetLoops(int, LoopType)1, Restart-1 loops forever; 0 is treated as 1.
SetDelay(float)0Seconds before the first cycle. Negative or non-finite means none.
SetAutoKill(bool)trueWhen off, a finished tween pauses at its end and stays alive for Restart or Rewind.
SetUpdate(UpdateType[, bool])Normal, falseWhich engine tick drives it: Normal, Late, Fixed or Manual.
SetUpdate(bool independent)falseIgnore GlobalTimeScale and keep running while gameplay is paused — for menus and UI.
SetTimeScale(float)1Per-tween speed; multiplies with the global scale.
SetRelative()offTreat the end value as an offset from the start. Call before it has run.
From() / From(bool relative)—Swap the endpoints and apply the new start immediately.
SetId(object) / SetTarget(object)noneTags for the bulk operations. See Ids, targets & globals.
SetLink(owner, isAlive)noneKill the tween as soon as isAlive(owner) returns false. Checked before each tick writes anything.

SetRelative and From are the two shortcuts for animating by an amount or into the current state:

Transform.MoveY(2f, 0.3f).SetRelative();   // up by 2 from wherever it is
Transform.Scale(0f, 0.4f).From();          // pop in: from 0 up to the current scale

Easing

Thirty named curves in three flavours: In starts slow, Out ends slow, InOut does both. These are drawn from the library's own equations with its default parameters; the faint diagonal in each is Linear, and the two faint rules mark the start and end values, so you can see where Back and Elastic overshoot.

InOutInOut

Vertical range −0.5 to 1.5 on every plot, so the overshoot is comparable across families. Bounce and Elastic are the only ones that cross the end value more than once.

For anything else, supply your own curve. It receives time normalised to 0–1 and should return 0 at the start and 1 at the end; values outside that range overshoot. You can also sample curves without creating a tween:

static readonly EaseFunction Stepped =
    static (t, duration, overshoot, period) => MathF.Floor(t * 4f) / 4f;

Transform.MoveX(5f, 1f).SetEase(Stepped);

float y   = Tween.EasedValue(0f, 10f, 0.5f, Ease.InOutSine);
float raw = EaseUtility.Evaluate(Ease.OutBack, 0.5f, overshoot: 3f);

Loops

SetLoops(count, type) repeats the tween. The loop type decides what each new cycle does:

  • Restart jumps back to the start value each cycle.
  • Yoyo plays forwards, then backwards. An even loop count lands back on the start value; an odd one on the end.
  • Incremental keeps adding the whole distance each cycle, so three cycles of 0→1 end at 3. A custom adapter must be unclamped for this to work.

With SetLoops(-1) a tween never completes. OnStepComplete fires at the end of each cycle; OnComplete never does.

Callbacks

Every callback has two overloads: a plain Action, and an allocation-free one that takes a state object and a static lambda.

// State form: pass what the callback needs; the lambda stays static.
Transform.Scale(1.1f, 0.2f)
         .OnStart(this, static s => s.PlaySound("pop"))
         .OnComplete(this, static s => s.ShowLabel());

// Capturing form: simpler, allocates the closure.
Transform.Scale(1f, 0.2f).OnComplete(() => Debug.Log("done"));
CallbackFires
OnStartThe first time the tween runs, after any delay
OnUpdateEvery time a value is applied
OnStepCompleteAt the end of each loop cycle — at most once per tick
OnCompleteAt the end of the final loop
OnKillWhen the tween is destroyed for any reason, including auto-kill and links
OnPlay / OnPauseWhen Play or Pause actually changes its state
OnRewindWhen Rewind is called

Within a tick the order is OnStart, the value, OnUpdate, OnStepComplete, OnComplete, then OnKill if it auto-kills. If any of them kills the tween, the rest are skipped. Callbacks may create, kill and control other tweens freely; a tween created inside a callback starts on the next tick.

One state per tweenAll the On*(state, …) overloads on a tween share a single state slot. Giving a second callback a different object re-points the first one at it, and the first callback then runs against an object of the wrong type. The library warns through TweenManager.Diagnostics when this happens — treat that warning as a bug. Pass the same state everywhere, usually this, and reach anything else through its fields.
// Wrong: `door` replaces `this` as the one state, so OnStart would run
// PlaySound against a Door. Logged as a warning when it happens.
Transform.Scale(1f, 0.2f)
         .OnStart(this, static s => s.PlaySound("pop"))
         .OnComplete(door, static d => d.Transform.MoveY(1f, 0.1f));

Playback & handles

Hold on to a handle when you need to control a tween later. Because dead handles are inert, a field that might hold a finished tween needs no null checks or bookkeeping:

private Tween _pulse;

public void StartPulse()
{
    _pulse.Kill();   // safe before the first assignment, and after it has died
    _pulse = Transform.Scale(1.05f, 0.5f).SetLoops(-1, LoopType.Yoyo);
}
_pulse.Pause();
_pulse.Play();
_pulse.TogglePause();
_pulse.Restart();                     // back to the start, playing
_pulse.Rewind();                      // back to the start, paused
_pulse.Goto(0.25f, andPlay: true);    // seconds, delay included
_pulse.Flip();                        // turn around from where it is
_pulse.Complete(withCallbacks: true); // jump to the end
_pulse.Kill(complete: false);

if (_pulse.IsActive && _pulse.IsPlaying && !_pulse.IsComplete)
    Debug.Log($"{_pulse.Elapsed} / {_pulse.FullDuration}, loop {_pulse.CompletedLoops}");
  • IsActive is true until the tween is killed or auto-kills; IsPlaying additionally requires it not to be paused.
  • Elapsed and Goto measure in seconds, delay and completed loops included. FullDuration counts an infinite tween as a single cycle.
  • Tween.None is the default handle, and every call on it is a no-op.

Sequences

A Sequence is a timeline of tweens and callbacks, and is itself a tween: you can ease it, loop it, await it, and nest it inside another sequence.

Sequence intro = Tween.Sequence()
    .Append(Transform.Move(new Float3(0, 2, 0), 0.4f))
    .Join(Transform.Scale(1.2f, 0.4f))
    .AppendInterval(0.2f)
    .AppendCallback(this, static s => s.PlayChime())
    .Append(Transform.Scale(1f, 0.25f))
    .SetLoops(2, LoopType.Yoyo);
MethodPlaces
Append(tween)At the end of the timeline so far
Join(tween)Alongside the most recent Append, starting at the same moment
Insert(seconds, tween)At an exact position
Prepend(tween)At the start, pushing everything else back
AppendInterval / PrependInterval(seconds)Empty time at the end or the start
AppendCallback([state,] callback)A callback at the current end
InsertCallback(seconds, [state,] callback)A callback at an exact position
 
intro.Insert(0.1f, Transform.RotateTo(new Float3(0, 90, 0), 0.3f))
     .Prepend(Transform.ScaleY(0.8f, 0.1f))
     .PrependInterval(0.1f)
     .InsertCallback(0.5f, this, static s => s.PlaySound("whoosh"));

// Not every overload is forwarded; the underlying handle has them all.
intro.Tween.OnStart(this, static s => s.PlaySound("start"));

Debug.Log($"{intro.Count} elements, {intro.Duration}s");
  • Adding a tween hands it over: the sequence drives it, turns its auto-kill off, and kills it when the sequence dies.
  • Each tween starts when the playhead reaches it, not before. That is when a shortcut reads its start value and fires OnStart, so consecutive moves each continue from where the previous one ended.
  • An empty sequence waits instead of completing, so you can create one and fill it over several frames. Composing a sequence that has already been killed does nothing and logs a warning.
  • The sequence's ease applies to its playhead as a whole, on top of each child's own ease.
  • Callbacks fire whenever the playhead crosses them, in either direction — so a Yoyo sequence fires them on the way back too.
  • If you lengthen a child after adding it, the timeline grows to fit from the next tick. Positions you set explicitly never move.
  • Sequence forwards the common setters and callbacks. For the rest — such as the state overload of OnStart — use sequence.Tween.

Awaiting

Tweens can be awaited instead of wired up with callbacks. You always name what you are waiting for, which keeps a fire-and-forget transform.Move(…) inside an async method from looking like a forgotten await.

public async Task ShowBanner(CancellationToken token)
{
    await Transform.Scale(1f, 0.3f).AsyncWaitForCompletion(token);
    await Tween.AsyncWaitForSeconds(2f, cancellationToken: token);
    await Transform.Scale(0f, 0.2f).AsyncWaitForCompletion(token);
}
WaitResumes when
AsyncWaitForCompletion()The final loop ends. An infinite tween only resumes when killed.
AsyncWaitForKill()The tween is destroyed
AsyncWaitForStart()It runs for the first time, after the delay
AsyncWaitForElapsedLoops(n)n cycles have finished
AsyncWaitForPosition(seconds)The playhead passes that time, delay included
Tween.AsyncWaitForSeconds(s)s seconds pass — unscaled by default
 
await Task.WhenAll(
    Transform.Move(new Float3(0, 1, 0), 0.5f).AsyncWaitForCompletion().AsTask(),
    Transform.Scale(2f, 0.8f).AsyncWaitForCompletion().AsTask());

Tween spin = Transform.RotateTo(new Float3(0, 360, 0), 2f);
await spin.AsyncWaitForPosition(1f);   // one second in
await spin.AsyncWaitForKill();
  • Every wait also ends when the tween dies, so an await never hangs on a tween that was killed early. Use callbacks if you need to tell the two apart.
  • Continuations run inline on the game thread, from inside the tick that satisfied them.
  • A cancellation token throws OperationCanceledException on the next tick. It cancels the wait, never the tween — kill it yourself if that's what you want.
  • .AsTask() is for Task.WhenAll and similar; awaiting directly is cheaper.

For a plain timer, DelayedCall is the callback equivalent. It also runs on unscaled time by default:

Tween.DelayedCall(1.5f, this, static s => s.Respawn());
Tween.DelayedCall(0.5f, () => Debug.Log("half a second, even while paused"));

Ids, targets & globals

Tag tweens with SetId (compared with Equals, so strings and enums work) or SetTarget (compared by reference), then control them together. Every bulk call has an overload with no filter that affects every live tween, and returns how many it touched.

Tween.DefaultEase = Ease.OutCubic;
Tween.DefaultAutoKill = true;
Tween.GlobalTimeScale = 0.5f;

Tween.PauseAll("hud");
Tween.PlayAll("hud");
Tween.CompleteAll(this);
Transform.KillTweens();
int killed = Tween.KillAll(this, complete: true);
Debug.Log($"{killed} killed, {Tween.TotalActive} still running");
GlobalDefaultPurpose
Tween.DefaultEaseOutQuadEase for tweens that don't choose one
Tween.DefaultEaseOvershootOrAmplitude1.70158Back overshoot and Elastic amplitude
Tween.DefaultEasePeriod0Elastic period; 0 means the standard value
Tween.DefaultAutoKilltrueWhether new tweens destroy themselves once complete
Tween.GlobalTimeScale1Speed of every tween not marked independent
Tween.TotalActive—Live tween count, across all value types
TweenManager.DiagnosticsDebug.LogWarningWhere misuse warnings go. Prowl wires this up; elsewhere it starts null and warnings are dropped.

Memory & cost

Once its arrays have grown, the library allocates nothing per frame — with or without callbacks and links. That is asserted by the test suite, not just claimed. What costs something is how you create tweens:

PathPer call
Tween.To(a, b, d).Bind(state, static …)Nothing
Tween.To<T, TAdapter, TState>(state, getter, setter, …)Nothing
transform.Move(…) and the other shortcutsNothing
On*(state, static …), SetLink(owner, static …)Nothing
Building and killing a SequenceNothing once its pool has warmed up
Bind(v => …), On*(() => …) capturing a variableA closure
Tween.To(() => …, v => …, to, d)Two delegates plus any closure
await …AsyncWaitFor*()The async state machine
…AsTask()A Task on top of that

Memory per live tween, measured: float 84 bytes and Float3 100 bytes; an id, target or link adds 32; any callback or custom ease adds 80; a tween still waiting to read its start value holds 16 until it does. These optional records live in separate arrays that are only allocated the first time a tween of that type uses them.

Storage grows by doubling and does not shrink on its own. Before a known burst, reserve; after it, trim:

ProwlTween.Reserve(512);                   // the float, Float3 and rotation storages
Tween.Reserve<Float3, Float3Adapter>(256); // one specific storage
Tween.Trim();                              // after the burst: hand the memory back

Custom value types

Any unmanaged struct can be tweened by writing an adapter: a readonly struct implementing ITweenAdapter<T>. Because it's a generic argument rather than an interface reference, the interpolation compiles straight into the update loop. Each (type, adapter) pair gets its own storage automatically.

public struct Bounds2
{
    public Float2 Min;
    public Float2 Max;
}

public readonly struct Bounds2Adapter : ITweenAdapter<Bounds2>
{
    // Must not clamp: LoopType.Incremental passes progress above 1.
    public Bounds2 Evaluate(in Bounds2 start, in Bounds2 end, float progress) => new()
    {
        Min = start.Min + (end.Min - start.Min) * progress,
        Max = start.Max + (end.Max - start.Max) * progress,
    };

    // Used by SetRelative().
    public Bounds2 Add(in Bounds2 a, in Bounds2 b) => new() { Min = a.Min + b.Min, Max = a.Max + b.Max };
}

// Then, anywhere:
Tween.To<Bounds2, Bounds2Adapter>(Crop, to, 0.4f)
     .Bind(this, static (v, self) => self.Crop = v);

Running outside Prowl

The core library — everything except ProwlTween, ProwlTweenAdapters, TransformTweenExtensions and TweenMaster — has no engine dependency; the test project compiles exactly that subset, so the boundary is checked on every build. In another host, drive the ticks yourself:

// Once, at startup. Leave RuntimeBootstrap null so nothing tries to spawn a driver.
TweenManager.Diagnostics = Console.WriteLine;

// Every frame.
Tween.FixedUpdate(fixedDt);            // as many fixed steps as the frame needs
Tween.Update(dt, unscaledDt);
Tween.LateUpdate(dt, unscaledDt);

// On shutdown, or around a hot reload.
TweenManager.Reset();
  • Each tick only advances tweens of its own UpdateType, but every tick reclaims killed tweens and resumes finished awaits, so a host that only calls FixedUpdate still works.
  • Pass the unscaled delta as the second argument if you want independent tweens to ignore pauses and slow motion; it defaults to the scaled one.
  • Everything is single-threaded: create, configure and tick tweens on one thread.
  • TweenManager.Reset() drops every tween without callbacks. Handles taken before a reset shouldn't be used after it.

Behaviour worth knowing

  • Every play session starts clean. Leaving play mode destroys the Tween Master, and every tween, pending await and changed global (DefaultEase, GlobalTimeScale…) goes with it. The next session's first tween spawns a new driver. The same happens if you destroy the master yourself mid-game.
  • Start values are read when a tween starts. The shortcuts and every getter-based form read the value when they actually begin — after their delay, or when a sequence reaches them. From() is the exception: it reads immediately, because it applies the new start straight away. Tweens built from explicit values use exactly what you gave them.
  • Two tweens on the same property fight. Both write every tick and the later one wins. Call transform.KillTweens() first, or keep the handle and kill it.
  • Euler rotations don't wrap. RotateTo(new Float3(0, 10, 0)) from 350° sweeps back through 180°. Target 370 (or −10) for the short way, or pass a Quaternion.
  • LookAt doesn't track. The target rotation is worked out once, when the tween is created.
  • Frozen isn't asleep. A tween with a time scale of 0 still fires OnStart and applies its start value once, then waits.
  • Long frames report cycles once. If a single tick crosses several loop cycles, OnStepComplete fires once for that tick, not once per cycle.
  • Integer tweens round half to even. An int tween passing 2.5 shows 2, and 7.5 shows 8.
  • Bad numbers are neutralised. A negative, NaN or infinite duration becomes an instant tween, and the same values for a delay or a frame delta are ignored, so a tween can't get stuck.
