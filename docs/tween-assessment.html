Verdict

Four axes

The core is genuinely well built: a dense array of unmanaged entries, a sparse slot table with versioned handles, struct adapters that the JIT devirtualises, and a steady-state update loop that allocates nothing. The problems are all at the edges — a cold-data array that the most common helper switches on for every tween, memory that only ever grows, a repeated-lookup pattern in the fluent API, and one build-level duplication that makes the whole thing ambiguous.

Strong core

Performance

Linear walk over contiguous entries, inlined adapters, no virtual dispatch per value. Undone in places by redundant handle resolution and per-entry update-type filtering.

sequence lookups/frame: 63 → 0 when nothing moved
Never returns any

Memory

Predictable and compact per tween, but every array is grow-only, the sweep runs on one tick type out of four, and nothing releases a tween when its target dies.

Zero, on the fast path

Allocations

The hot loop and the Bind(state, …) creation path are allocation-free. The convenient overload costs four allocations per call and has no allocation-free twin.

Coherent, loose ends

Design

Handle semantics, doc comments and layering are unusually disciplined. Undermined by a duplicated assembly reference, a hot-reload hazard, and several silent traps.

What changed

Applied & measured

Everything in the ranked list at the bottom has been applied. The library still has no dependency on the engine: the portable half stays in Prowl.Tweening, the four engine-coupled files (ProwlTween, ProwlTweenAdapters, TransformTweenExtensions, TweenMaster) sit in Prowl.Runtime around it, and the test project compiles only the portable half — which makes that boundary a standing build-time check rather than a convention.

Tagged tween196 B → 132 B
Cold array reads/tick4 → 0
  • The duplicate definition is gone at the build level, not the file level. Prowl regenerates the .csproj on every recompile, so deleting the <Reference> by hand would not have survived. It is now removed in Directory.Build.targets, which MSBuild imports after the generated project body and which Prowl never touches — one commented ItemGroup to delete if the library ever moves back out.
  • Identity split from callbacks. TweenTags (32 B: id, target, link) and TweenEvents (80 B: eight delegates plus state) are separate lazily-allocated arrays behind separate flags. SetTarget no longer drags the callback record into the hot loop.
  • Handles resolve once per call. Storage() used to compute the dense index and throw it away, leaving CoreRef to recompute it; TryGet now returns both. Sequences cache their children's dense indices and revalidate them against a compaction stamp, so a steady-state sequence does no slot-table lookups at all.
  • Lifetime links. SetLink(owner, isAlive) is checked at the start of every tick, before any value is applied, and the transform helpers apply it by default — so a tween can no longer write to a destroyed GameObject.
  • Reset is the reload seam. TweenManager.Reset() drops the registrations; Of<T, TAdapter> then notices its storage is no longer registered and makes a fresh one. TweenMaster's module initializer calls it, which is what runs after a hot reload. The same method is what isolates each test.
  • Two bugs the tests found, not the review. Fixing the yoyo callback direction introduced a regression where the loop-counter change at final completion flipped the playhead direction and swallowed a callback near the end; and Pause/Play exposed that all On*(state, …) overloads share one state slot, so two different state objects silently collide. The first is fixed; the second now warns through the diagnostics hook — it is a deliberate trade-off (one slot rather than eight references per tween), just no longer a silent one.

What it already gets right

Keep these

  • The storage shape is correct. TweenStorage<T, TAdapter> packs TweenCore + start + end inline in one dense array with no holes, and structural removal is batched into Sweep rather than done per kill — so a kill from inside a callback can never invalidate the loop's indices.
  • Handles are 12 bytes and fail safe. Slot + version means a stale Tween stops resolving instead of dangling, and entries can be swapped during compaction without invalidating anything the user holds.
  • Adapters are struct generic arguments, not interfaces. default(TAdapter).Evaluate(…) devirtualises and inlines; there is no boxing and no per-value delegate call.
  • The update loop allocates nothing. Action<T, object?> over an unmanaged T does not box, and Fire reuses the stored delegate. This is the property most tween libraries fail, and this one holds it.
  • Awaits are polled, not hooked. TweenAwaiterRegistry deliberately avoids stealing the user's OnComplete delegate, and a program that never awaits pays one if per tick.
  • The doc comments are real. They explain intent and trade-offs, not signatures — including the reentrancy rules around "user code below this line", which is exactly where this kind of library breaks.

Findings

Axis · severity · location

PERF

Tagging a tween puts it on the cold-data path forever High

SetId and SetTarget both route through EventsRef, which allocates _events and sets HasEvents. Step then reads _events[dense] four separate times per tick to check callbacks that were never assigned. Identity and callbacks are different concerns sharing one flag.

TweenStorage.cs:170–181TweenStorage.cs:290, 303–317Tween.cs:253–266TransformTweenExtensions.cs:159

Fix Split Id/Target into their own small array (or a side dictionary keyed by slot, since bulk kills are rare and cold), and gate the hot path on a separate HasCallbacks flag set only by the On* methods.

PERF

Every fluent call resolves the handle twice Medium

Storage() performs Resolve plus IsAlive — which computes the dense index — then returns only the storage, so CoreRef recomputes the same index. Sequence composition is the worst case: Append costs eight lookups across Data, Adopt and SyncDuration.

Tween.cs:33–41TweenStorage.cs:142–181Sequence.cs:47–59, 164–169

Fix Add an internal bool TryResolve(out ITweenStorage storage, out int dense) and a dense-indexed CoreAt(int dense). The fluent methods then resolve once. For sequences, cache the resolved storage reference on SequenceData alongside Owner.

PERF

Update type is filtered per entry, not partitioned Medium

Update walks the whole dense array and skips on c.UpdateType != type. Today s_usesUpdateType saves you: Late, Fixed and Manual are all false until someone opts in. The moment a single tween calls SetUpdate(UpdateType.Fixed), every storage's full array is walked on every fixed step, which may run several times per frame.

TweenStorage.cs:227–247TweenManager.cs:25, 133–144

Fix Cheapest: keep a per-storage count of entries per update type and skip the walk when it is zero. Cleaner: partition the dense array into four contiguous ranges and let Sweep maintain the boundaries.

PERF

Sequences pay per child, per frame, through the interface Medium

SequenceData.Evaluate reads Owner.CompletedLoops (three lookups) and then, for each child, does Resolve + IsAlive + Goto — three more lookups and a non-inlinable interface call. Children also remain in the main dense array and are re-tested by flag on every tick even though only the sequence drives them.

Sequence.cs:340–385TweenStorage.cs:236

Fix Store the resolved dense index on each Element and invalidate it in Sweep; or move sequenced entries to the tail of the dense array so the main loop's range excludes them.

PERF

The runtime bootstrap runs on every single tween creation High

Create calls EnsureRuntime() → TweenMaster.Ensure() per tween. The happy path is three chained validity checks. The unhappy path — driver null or its scene invalid, which is exactly what a scene transition produces — runs Scene.Current.FindObjectsOfType<TweenMaster>(), a full scene-graph scan with an allocation, for every tween created.

TweenStorage.cs:73TweenManager.cs:82–86TweenMaster.cs:45–81

Fix Latch a static bool s_installed once a driver exists and return immediately; re-arm it only from an explicit scene-load / driver-destroyed hook rather than by re-probing the scene.

PERF

AggressiveInlining on a 70-line switch Low

EaseUtility.Evaluate is far past the JIT's inlining budget, so the attribute is almost certainly ignored — and if it were honoured it would bloat Step and hurt the icache. It is a misleading signal either way.

EaseUtility.cs:93–166

Fix Drop the attribute, or keep an inlined fast path for Linear/Quad/Cubic and tail-call a [MethodImpl(NoInlining)] method for the rest.

MEM

Nothing ever shrinks, and there is no API to ask Medium

_entries, _bindings, _events, _slots, SequenceData._elements and s_waiters all double on demand and stay at their high-water mark for the life of the process. A one-frame burst of 10,000 Float3 tweens permanently pins roughly 2 MB in that storage. The pooled SequenceData instances keep their grown Element[] too, so one 4,096-element sequence retains that array in the pool.

TweenStorage.cs:109–116, 128–130Sequence.cs:333–337, 398TweenAwaiter.cs:156–158

Fix Add TweenManager.Trim() (shrink each storage to _count rounded up, and drop _events entirely when no live tween has HasEvents) plus a Reserve(int) so callers can pre-size instead of doubling mid-frame. Cap the pooled element array length, not just the instance count.

MEM

Sweep runs on one tick type out of four High

TweenManager.Update sweeps; LateUpdate, FixedUpdate and ManualUpdate do not. Dead entries are cheap to skip, but they still hold their Binding.State and TweenEvents object references — so a killed tween keeps its target object and captured state alive until the next Normal tick. A host that drives only the fixed step never reclaims anything.

TweenManager.cs:101–131TweenStorage.cs:479–511

Fix Sweep from whichever tick ran, guarded by _deadCount != 0 (already the first line of Sweep, so this is nearly free), or expose TweenManager.Collect() and call it from all four.

MEM

A tween outlives its target with no link High

Nothing kills a tween when the object it animates is destroyed. Binding.State holds a strong reference, so destroying a GameObject mid-tween leaves the setter running against a detached Transform every frame — a leak and a latent crash at once. The static registry survives scene unload, so this persists across scene loads.

TweenStorage.cs:44–48, 306–307TransformTweenExtensions.cs:156–159

Fix A SetLink(object owner) that stores a validity predicate (or an EngineObject the storage can null-check) and auto-kills on the next tick when it fails; the transform helpers should apply it by default. At minimum, have TransformTweenExtensions call KillTweens from the component's destroy path.

MEM

Statics in generic types do not survive hot reload High

The build emits five EMBA001 warnings for exactly this. TweenManager.Of<T, TAdapter>.Storage is the dangerous one: after a reload it re-runs and registers a fresh storage, while the old one stays in s_storages and keeps getting ticked. You get duplicated ticking, orphaned tweens driving stale delegates, and a leak on every reload.

TweenManager.cs:46–51Tween.Static.cs:305–308TweenBuilder.cs:29TweenStorage.cs:61–62

Fix Move the per-type storage lookup out of the generic type — a non-generic registry keyed by typeof(T)/typeof(TAdapter), with the generic field only caching the id — or apply [ReloadIgnore] and add an explicit TweenManager.Reset() that the reload hook calls.

ALLOC

The convenient overload has no allocation-free twin High

Tween.To(getter, setter, …) costs two closure objects plus two delegates per call, and it is the one path this game actually uses: TransitionManager.Transition allocates four objects per screen transition. The library documents the cost and points at Bind, but Bind cannot read a start value, so there is no non-allocating way to express "tween from wherever it is now".

Tween.Static.cs:262–303TransitionManager.cs:27–30

Fix Add To<T, TAdapter, TState>(TState state, Func<TState, T> getter, Action<T, TState> setter, T to, float duration) using the same erased-delegate trick as Bind<TState>. Both lambdas then stay static and the path is allocation-free.

DESIGN

The library is compiled twice and the copies disagree High

372 of the build's 377 warnings are CS0436: every type here collides with the same type in the referenced Prowl.Tweening.dll, and the local source silently wins. The upstream Prowl/Prowl.Tweening/ folder now contains only obj/ — the sources were moved into Assets/Scripts for iteration and the stale assembly reference was never removed. Anything you add here is invisible to that DLL's other consumers.

Quick — …Game.csproj:106–107Quick — …Editor.csproj:106–107

Fix Pick one home. Either drop the two <Reference Include="Prowl.Tweening"> blocks and keep developing in Assets/Scripts/Tween, or move the sources back to Prowl.Tweening and reference the project. Do this first — the other findings are hard to verify while two definitions are in flight.

DESIGN

A sequence built across two frames is already dead High

Sequence.Create produces a live, unpaused tween with Duration = 1e-6 and auto-kill on. Hold the handle for one frame before appending and it has completed, auto-killed, and recycled its SequenceData back to the pool — after which every Append resolves Data to null and silently no-ops. Nothing warns.

Sequence.cs:33–42TweenStorage.cs:268–299

Fix Create the owner paused and add an explicit Play() requirement, or give it a "building" flag that Step skips until the first element is added. Either way, make a no-op Append on a dead sequence loud in debug builds.

DESIGN

Sequence timelines freeze their children's durations Medium

Adopt captures core.FullDuration at insertion time and the timeline never re-reads it. Calling SetDelay, SetLoops or changing a duration on a child after it has been appended desynchronises the sequence silently — the child is then clamped to a window that no longer matches it.

Sequence.cs:289–299, 369–381

Fix Recompute each element's window from the child's live FullDuration during Evaluate (you already resolve the storage there), or lock configuration on adopted tweens and say so.

DESIGN

Cross-thread awaits are advertised but not safe Medium

TweenAwaiterRegistry takes a lock because "registration can come from any thread", but TweenAwaiter.IsCompleted → IsSatisfied reads the storage's dense arrays with no synchronisation at all, and CoreRef writes the shared static s_noCore when a handle misses. An await registered from a pool thread can therefore race the game thread's tick.

TweenAwaiter.cs:104, 136–138, 224–241TweenStorage.cs:61–62, 161–181

Fix Decide the contract. Either declare awaits main-thread-only (matching TweenManager's own single-threaded doc) and drop the lock, or queue registrations through a lock-free inbox that the pump drains, and never touch storage off-thread.

DESIGN

Shared mutable statics as the dead-handle sink Medium

s_noCore and s_noEvents let CoreRef return a writable reference for a handle that no longer resolves. Writes silently vanish, two stale handles can observe each other's writes, and the "every operation on a dead handle is a no-op" guarantee becomes "…usually". It is also the reason two of the EMBA001 warnings exist.

TweenStorage.cs:60–62, 161–181

Fix Replace with bool TryGetCore(int slot, int version, out int dense) and let callers branch. The public surface already wants to no-op explicitly, so the scratch sink buys nothing.

DESIGN

Silent traps in the semantics Medium

Five places where behaviour differs from what the code or docs imply:

  • Ease.Unset is documented as resolving to Tween.DefaultEase, but Create writes the default directly and EaseUtility falls through Unset to return t — so SetEase(Ease.Unset) quietly means Linear.
  • Tween.EasedValue uses EaseUtility's own 1.70158f const rather than Tween.DefaultEaseOvershootOrAmplitude, so changing the global default does not affect it.
  • If a setter kills its own tween, Step carries on firing OnUpdate, OnStepComplete and OnComplete on the now-dead tween.
  • TimeScale = 0 is skipped before Step, so such a tween never fires OnStart and never reports as started.
  • Sequence callbacks fire only while the playhead moves forward, so LoopType.Yoyo never fires an inserted callback on the reverse pass — and a callback sitting at position 0 is missed after Restart.
Enums.cs:113EaseUtility.cs:164Tween.Static.cs:338TweenStorage.cs:242, 306–317Sequence.cs:351, 359
DESIGN

No input validation on time Medium

duration is clamped against negatives but not against NaN or Infinity, and neither is delay or the incoming delta. One NaN makes c.Position >= duration permanently false: the tween never completes, never auto-kills and is never swept. Separately, a zero-duration tween is clamped to MinDuration = 1e-6, so a single 16 ms frame computes roughly 16,000 loop steps — reported as one OnStepComplete, and on an infinite loop CompletedLoops will eventually overflow.

TweenStorage.cs:88, 268–285, 313

Fix Reject non-finite duration/delay/delta at the boundary, clamp steps, and fire OnStepComplete once per cycle actually crossed (or document the collapse).

DESIGN

Unverifiable delegate reinterpretation Low

Three sites cast Action<TState> to Action<object?> via Unsafe.As to avoid a closure. The where TState : class guard is the right one and this works on CoreCLR and NativeAOT today, but it is outside the spec — a future IL verifier, trimming pass, or a different runtime is where it would surface, and the failure mode is silent memory corruption rather than an exception.

Tween.cs:382–393TweenBuilder.cs:53–61Sequence.cs:154–162

Fix Keep it, but add a Debug.Assert that the delegate's target type is a reference type, and a single comment naming the assumption so it is greppable if a runtime ever breaks it.

DESIGN

API gaps and asymmetries Low

  • Tween.To has concrete overloads only for System.Numerics types. Prowl's own Float2/3/4, Quaternion and Color need the verbose Tween.To<Float3, Float3Adapter>(…) because the adapters live in Prowl.Runtime, which Prowl.Tweening cannot reference. A ProwlTween façade in Prowl.Runtime closes it.
  • Sequence passthrough is missing Goto, Flip, TogglePause, OnPlay, OnPause, OnRewind and SetUpdate(bool), so callers drop to .Tween and lose the chain.
  • Global defaults are mutable public static fields — no validation and not binary-compatible. Properties, or a single TweenSettings struct, would be safer.
  • LookAt resolves its rotation once at creation and will not track a moving target; RotateTo(Float3 euler) interpolates raw angles, so 350° → 10° takes the long way round. Both are defensible, neither is documented.
  • TweenMaster is the only file with no namespace, sitting in the global one.
Tween.Static.cs:190–199, 221–242Sequence.cs:175–196TransformTweenExtensions.cs:216–252TweenMaster.cs:1–16
DESIGN

No tests, no benchmarks, and nullability is unenforced High

For a library whose whole pitch is "dense, allocation-free, handle-safe", the invariants that matter are exactly the kind that regress silently: version bumps on kill, sweep correctness when a callback creates or kills tweens, yoyo and incremental loop maths, and zero steady-state allocation. None of them are covered. ManualUpdate means a test project needs no engine at all. Both csproj files also set <Nullable>annotations</Nullable>, so the careful ? annotations throughout produce no warnings.

TweenManager.cs:127–131Quick — …Game.csproj

Fix One xUnit project driving Tween.ManualUpdate with a fixed step, plus a GC.GetAllocatedBytesForCurrentThread assertion around a 1,000-tween 600-tick loop to lock the zero-allocation claim in. Raise nullable to enable for the library's own files.

What to fix, in order

Ranked by impact ÷ effort

The ordering was a real sequence, not a list of equals: items 1–3 were prerequisites for trusting anything measured afterwards, and 4–8 were where the remaining runtime cost sat. All eighteen are now applied; the effort figures are the original estimates, kept for calibration.

  1. Resolve the duplicate assemblyHighDone~10 min

    Drop the two Prowl.Tweening references, or move the sources back and reference the project. 372 of 377 build warnings go with it, and every later change becomes verifiable.

  2. Fix the hot-reload storage leakHighDone~half a day

    Move the per-type storage out of Of<T, TAdapter>, or add [ReloadIgnore] plus an explicit TweenManager.Reset(). Right now every reload duplicates ticking and orphans live tweens.

  3. Add the test projectHighDone~1 day

    Drive ManualUpdate with a fixed step; cover handle versioning, sweep-under-callback, loop maths, and an allocation assertion. Nothing here needs the engine, and every finding below becomes a regression test.

  4. Separate identity from callbacksHighDone~2 hours

    Stop SetTarget/SetId from setting HasEvents. This alone takes the normal transform tween from 196 B back to ~112 B and removes four cold-array reads per tween per tick.

  5. Latch the runtime bootstrapHighDone~30 min

    A full scene scan per tween creation is the single worst cliff in the library, and it only shows up during scene transitions — the exact moment you are creating the most tweens.

  6. Sweep from every tickHighDone~15 min

    Sweep already early-returns on _deadCount == 0, so calling it from all four ticks is nearly free and stops killed tweens from pinning their targets.

  7. Link tweens to target lifetimeHighDone~half a day

    A SetLink that auto-kills when its owner is destroyed, applied by default in the transform helpers. Currently a destroyed object keeps being animated across scene loads.

  8. Add an allocation-free getter/setter overloadMediumDone~1 hour

    To<T, TAdapter, TState>(state, getter, setter, to, duration). The only tween call site in this game is on the 4-allocation path because no alternative exists.

  9. Resolve handles once per callMediumDone~3 hours

    An internal TryResolve(out storage, out dense) plus dense-indexed accessors halves the lookups in the fluent API and cuts a 20-child sequence's per-frame hops from 63 to about 23.

  10. Make sequences safe to build over timeMediumDone~2 hours

    Create the owner paused or in a "building" state, and make a no-op Append on a dead sequence loud in debug. Silent no-ops here are very hard to diagnose.

  11. Validate time inputsMediumDone~1 hour

    Reject non-finite duration, delay and delta; clamp steps. A single NaN currently creates a tween that can never complete and can never be swept.

  12. Decide the threading contract for awaitsMediumDone~2 hours

    Either main-thread-only (and drop the lock) or a proper lock-free inbox. Today the registry claims thread safety that IsSatisfied does not provide.

  13. Partition or count update typesMediumDone~2 hours

    A per-storage per-type count is the cheap version and removes the cliff the first SetUpdate(Fixed) call introduces.

  14. Add Trim() and Reserve()MediumDone~2 hours

    Let callers pre-size before a burst and hand memory back after one. Cap the pooled sequence element arrays by length, not just instance count.

  15. Replace the static scratch sinksLowDone~1 hour

    TryGetCore(out …) instead of s_noCore/s_noEvents. Restores the dead-handle guarantee and removes two of the reload warnings.

  16. Close the semantic trapsLowDone~2 hours

    Ease.Unset, the split overshoot default, callbacks firing after a kill, TimeScale = 0 suppressing OnStart, and yoyo sequences skipping reverse callbacks — each is small, and each will cost someone an afternoon.

  17. Fill the API gapsLowDone~half a day

    A ProwlTween façade for the engine's own math types, the missing Sequence passthroughs, defaults as properties, and doc lines on LookAt and euler RotateTo.

  18. HousekeepingLowDone~20 min

    Delete the orphan Controller.meta, drop the misleading AggressiveInlining on EaseUtility.Evaluate, give TweenMaster a namespace, and raise the library to <Nullable>enable</Nullable>.

Verified since. The zero-allocation claim is no longer a reading of the code: AllocationTests asserts an exact zero GC.GetAllocatedBytesForCurrentThread delta across 500 ticks of 200 live tweens (and again with callbacks and links in play), across 200 creations, and across 200 build-and-kill sequence cycles — with tiered compilation disabled for the test assembly so the JIT cannot charge its own allocation to the library.
